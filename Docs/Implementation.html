CharaVoice 技术实现说明

本地角色声音服务：GPT-SoVITS / OmniVoice 合成与微调、sherpa-onnx 听写、声线调节与自然度后处理、素材流水线、Tauri 界面、Agent 接口与安装包。本文只讲接入和复现所需的要点。

1. 整体结构

  • 引擎永远作为独立进程运行，后端不 import 它的代码。整合包自带 Python，和后端的 3.11 虚拟环境互不影响。
  • 后端用 Windows 作业对象（JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE）托管所有子进程；Tauri 用 set_process_group(true) 启动后端。任何一层退出，下面的进程都会被系统回收，不留占显存的僵尸进程。
  • 后端另外监视父进程 PID（--parent-pid），Tauri 崩溃时自行退出。

2. 合成（说）

  1. 启动：runtime\python.exe -I api_v2.py -a 127.0.0.1 -p 9880 -c data/engine/tts_infer.yaml，配置只写 custom 段（device、is_half、version、权重路径）。api_v2 没有健康检查接口，用 GET /docs 探活。
  2. 每个声音的请求带自己的参考音频与参考文本；权重不同就先调 /set_gpt_weights、/set_sovits_weights（引擎会按文件自动识别版本）。
  3. POST /tts 用 streaming_mode=1（逐句返回）：首包是只有头的 WAV，之后是裸 PCM，按 2 字节对齐切块，边收边播放。
  4. 播放线程每 30ms 写一块、同时算电平推给界面，所以 Agent 通过接口说话时圆环也会动。
  5. 流式模式：1 = 逐句（音质最好）、2/3 = 按语义 token 分块（3 最快，首包约 0.2 秒）。HTTP 流式响应的客户端中途断开时，生成器的 finally 标记任务放弃，合成循环随即退出并 aclose() 引擎流，引擎锁立刻释放；否则下一个请求要排在被丢弃的合成后面，首包会多出约 1 秒。
  6. 可选引擎 OmniVoice（独立虚拟环境 + 自写的 engine_scripts/omnivoice_server.py，按句流式）。两个引擎不同时占显存：启动一个前先停另一个（切换约 15 秒）。
参考音频必须 3-10 秒（引擎在 TTS.py 里硬性检查）。参考文本为空时后端用 SenseVoice 自动转写。语种按文字自动判断：含假名为日语，含汉字为中文，否则英语。

3. 听写（听）

麦克风 16kHz → 每 30ms 一块送 Silero VAD（is_speech_detected() 的上升沿推 speech_start）→ VAD 弹出片段时推 speech_end → 独立线程用 SenseVoice 识别并推 transcript（文字、语种、情绪）。单次 listen 把间隔小于 turn_silence（默认 1.2 秒）的片段拼成一句再返回。角色说话时默认暂停听写，避免录进自己的声音。

全局听写

  • Rust 用 tauri-plugin-global-shortcut 按候选列表注册第一个空闲的组合（Ctrl+Alt+Space 常被其他程序占用，依次退到 Ctrl+Shift+Space、Alt+Shift+D）。注册失败不能 panic，要在运行时逐个尝试。
  • 听写小窗启动时就以隐藏状态建好（focusable(false)、置顶、透明），按键时只 show() 并发事件。窗口不可获得焦点，用户原来的输入框保持光标，第一次按键也不会因为加载网页漏掉开头的话。
  • 后端听一轮：VAD 关闭片段时给出 end_lag（实际说完到现在的样本数），以“真正说完”的时刻起算 0.7 秒（可设置）结束；识别完用 SendInput + KEYEVENTF_UNICODE 逐字符输入，中日文不经过输入法。实测说完到出字 0.70-0.74 秒。

4. 素材流水线

  • 裁剪后的多个保留段拼成一个文件（段间垫 1 秒静音）一次性分离；切出的句子时间再换算回原始素材时间（落在垫片里的就吸附到最近的保留段边界）。
  • 人声分离用一个很薄的驱动脚本 engine_scripts/uvr_separate.py，由整合包的 Python 执行，调用它的 Roformer_Loader._path_audio_()；输入需先转成 44.1kHz 立体声，输出 <名字>_vocals.wav。
  • 声纹相似度：sherpa-onnx SpeakerEmbeddingExtractor + 3D-Speaker CAM++（中英通用）。默认目标是该声音的参考音频，也可以用勾选的片段平均。实测同一人 0.86-0.96，不同人约 0.02-0.15。
  • 质量分 = 时长分 × 信噪比分 × 削波惩罚（信噪比用帧能量 90/10 分位估算，只作排序参考）。
  • 回环录音：PyAudioWPatch 把每个 WASAPI 输出设备复制成 [Loopback] 输入设备。PyAudio 实例、打开流和读流必须在同一线程，否则报 PortAudio -9999；设备空闲时回环不给数据，按真实时间补静音。

5. 训练

要点做法
参数传递和 webui.py 一致：准备脚本全部读环境变量（inp_text、inp_wav_dir、opt_dir、i_part/all_parts、version、is_half…）；训练脚本读由模板改写的配置（configs/s2v2ProPlus.json 或 s2v2Pro.json、configs/s1longer-v2.yaml）。默认底模是 v2ProPlus：同样 10 分钟素材，比 v2Pro、V5 turbo LoRA、VoxCPM2 LoRA、Qwen3-TTS 微调都更像，速度与 v2Pro 相同。语义 token 由底模自己的量化器提取，按底模分别存成 6-name2semantic-<版本>.tsv。用 runtime\python.exe -s 执行。
目录实验目录与权重输出都指向声音自己的文件夹（data/voices/<id>/train/exp、weights/），不写引擎目录。启动 s2 前必须先建 exp/logs_s2_<版本>，否则第一次保存检查点就失败。
断点续训s2 从 logs_s2_<版本> 里最新的 G_/D_ 检查点续；s1 由 Lightning 从 ckpt/ 续。准备阶段产物存在就跳过。所以“继续训练”就是用同一目录重新跑。
显存训练前停掉推理引擎，并在训练期间拒绝合成请求（返回明确提示）。批量按空闲显存 GB ÷ 2 估算（webui 用总显存 ÷ 2）。
进度s2 解析 ====> Epoch: N；s1 解析 Lightning 的 Epoch N: xx%。中断用 taskkill /T 结束整个进程树（含 DataLoader 子进程）。

简易模式：素材文件夹一键克隆（日语）

要点做法
数据一个素材文件夹就是一个声音（voice.json 里 folder: true，语言固定 ja）。片段存在 data/voices/<id>/clips/，元数据在 clips.json（时长、标签、来源录音、截取区间、CAM++ 声纹）。被截取的原始录音以 FLAC 存在 data/recordings/，所以片段可以随时重新裁剪；没有片段引用的录音在删除片段时、或放置 3 天后自动清理。
快捷键录制Tauri 全局快捷键按顺序尝试 Ctrl+Alt+R、Ctrl+Alt+Shift+R、Alt+Shift+R、Ctrl+Alt+F9（不用 Ctrl+Shift+R，它是浏览器的强制刷新）。按下后显示一个预先创建的、不抢焦点的置顶小条，由它调用 /v1/simple/record/toggle，所以主窗口最小化时也能用；停止后后端发 simple_recorded 事件，小条把主窗口还原，主窗口打开截取编辑器。同一次按键 700 ms 内只触发一次。
截取建议Silero VAD 切出语音段，首尾建议 = 第一段开始前 0.2 秒到最后一段结束后 0.3 秒。每段（≥0.8 秒）算 CAM++ 声纹，返回段与段之间的相似度矩阵，以及与文件夹已有片段平均声纹的相似度。基准优先用文件夹已有片段，没有时用第一段，用户可以双击任意段改为基准；低于 0.5 的段默认去掉。JVNV 实测：同一女声各段 0.55-0.73，混入的男声 0.26-0.36。
一键克隆把文件夹全部片段作为来源送进素材流水线（人声分离、切句、转写），语种统一标为 ja；取与整体平均声纹最接近的一半语句求目标声纹，删掉相似度低于 0.45 或质量分低于 15 的句子；挑 3-10 秒里质量分最高的一句作零样本参考（底模 V5 turbo）。有效语音 ≥1 分钟且用户选择训练时，再以 v2ProPlus 训练（fresh），训练期间合成暂停。片段集合的指纹记录在 clips.json，片段变化后界面提示“重新学习”。
朗读与导出界面按 。！？ 和换行分句（过短的并入后句，超过 120 字在 、 处再切），逐句请求 /v1/audio/speech，播放第 i 句时预取 i+1、i+2，暂停 / 停止由界面控制。导出走 /v1/simple/folders/<id>/export：整篇分块合成、拼接后统一加水印和“AI 合成”元数据，写到 data/exports/。

6. 声线调节与自然度

环节做法与实测
音高自写 TD-PSOLA：基频用 pyworld 的 DIO + StoneMask，在约 16kHz 副本上算、allowed_range=0.2（默认值会把 15-45% 的有声帧判成无声，变调量明显不足），40ms 以内的无声空隙线性补齐；分析标记按 F0 周期放置，不要对齐波形峰值（对齐后预测 MOS 低 0.4）；输出按窗口和的 20ms 平滑值归一化，逐点除会把新的脉冲串抹平。每秒音频约 10ms。对比：WORLD 只做分析重合成 MOS 就从 3.54 降到 2.58，stftpitchshift 变调 MOS 1.39，Signalsmith 会连共振峰一起移。
年龄感 / 明亮度 / 气声一次 STFT（约 32ms 帧，保留原相位）：对数幅度谱的低倒谱（1.5ms 以内）得到包络，除掉包络后按频率缩放包络再乘回（共振峰），叠加以 1kHz 为轴的倾斜（明亮度），1.5kHz 以上在语音帧加包络形状的噪声（气声）。±10% 共振峰 MOS 3.28/3.12（原声 3.54）。
流式voicefx.Stream 每次最多处理 1 秒，带 80ms 左上下文、40ms 预读，块间 10ms 交叉淡化；块处理在线程里逐个取出，首块额外延迟 5-18ms。
停顿CharaVoice 自己按标点切句、逐句请求引擎（text_split_method=cut0），去掉引擎自带的头尾静音后按标点插入停顿（逗号 0.2s、句末 0.45s、省略号 0.5s、换段 0.8s，±15% 抖动，随语速缩放）；第一句不与后句合并，保证首包不变慢。
呼吸从声音自己的素材里找无 F0、电平在语音下 12-40dB、150-500ms、其后 0.6s 内有语音的片段，按原始相对电平保存；插入在较长新句之前的停顿里。修剪过的朗读素材通常找不到。
后处理5ms 块 RMS 压缩（2:1）、5-9kHz 动态去齿音、pyloudnorm 测响度到 -16 LUFS（首句定增益，之后缓慢跟随）、合成小房间脉冲响应（RT60 约 0.3s，湿声 -26dB）、-62dBFS 粉红底噪、软拐点限幅。用 UTMOS22 在同一批音频上逐项测：压缩 -0.08、响度 -0.04、混响 -0.10、底噪 -0.04，所以默认只开停顿和响度。
MOS 预测模型偏爱“干”声，混响、底噪、呼吸都会被它当成劣化；这类处理是否更像真人，要用盲听判断。

7. Agent 接口

接口说明
POST /v1/audio/speechOpenAI 兼容；model/voice = 声音 id；language、response_format、stream、play（false 只返回音频）。非流式输出带 AudioSeal 水印和“AI 合成”元数据。
POST /v1/speak播放并返回 JSON；wait=true 等播完。
POST /v1/audio/transcriptionsOpenAI 兼容转写，返回 text / language（verbose_json 带分段）。
POST /v1/listen、WS /v1/listen听一句；实时事件 speech_start / speech_end / transcript。
MCPspeak、list_voices、listen、transcribe；基于 MCP Python SDK 2.x 的 MCPServer。stdio 用 charavoice-backend.exe mcp；Streamable HTTP 挂在后端 /mcp：自己建 StreamableHTTPSessionManager(app=server._lowlevel_server)，在 FastAPI 的 lifespan 里 async with manager.run()，路由用一个检查口令后转给 manager.handle_request 的 ASGI 对象，并限定 Host/Origin 为本机（防 DNS 重绑定）。
按 Agent 分配声音调用方名字依次取：环境变量 CHARAVOICE_AGENT、请求头 X-CharaVoice-Agent、MCP 握手里的 client_params.client_info.name。后端记到 data/agents.json，请求没指定 voice 时用绑定的声音和默认情绪。
口令运行时口令每次启动重新生成（data/runtime.json）；另有长期有效的 Agent 口令（data/agent_token），给需要写进配置的 MCP HTTP / OpenAI 客户端用。
能力发现GET /.well-known/charavoice.json 列出接口、MCP 工具和可用参数。
claude mcp add --transport http charavoice http://127.0.0.1:9870/mcp --header "Authorization: Bearer <Agent 口令>"

8. 安装包与模型管理

  • 后端用 PyInstaller 冻结为单目录 charavoice-backend.exe（同一个 exe 是后端 serve、命令行和 stdio MCP），作为 Tauri 资源打进 NSIS 安装包（按用户安装，约 150MB）。mcp 包不要整体收集（mcp.cli 依赖 typer），只收 mcp.server、mcp.shared。
  • 冻结后的后端默认数据目录是 %LOCALAPPDATA%\io.github.rudans.charavoice，和 Tauri 的 identifier 一致，所以命令行和 MCP 不需要任何配置就能找到运行中的后端。
  • 模型与引擎在“模型”页下载：断点续传（Range）、进度事件、GPT-SoVITS 整合包用下载来的 7zr.exe 解压、OmniVoice 用下载来的 uv 建环境。删除只允许删除数据目录里的内容。
  • 没有 ffmpeg 时，WAV/FLAC/OGG/MP3 用 soundfile 解码、scipy 重采样。

9. 踩过的问题

现象原因与处理
引擎日志乱码python -I 会忽略 PYTHONIOENCODING，子进程按系统 ANSI 代码页输出；读管道时用 locale.getencoding() 解码。
偶发合成卡几分钟显卡被其他程序占满（模拟器、编辑器）时会出现；后端 90 秒无输出就报错并自动重启引擎。CUDA Graph 首次遇到新长度需要捕获，启动后先做一次预热。
两个窗口同时检测到后端退出，拉起两个后端Rust 侧用异步互斥锁串行化 backend_info；后端发现端口已占用直接退出。
热更新后 WebGL 退回静态图组件卸载时不要 loseContext()，同一个 canvas 可能被复用；只释放缓冲区和程序。
AudioSeal 报找不到 cl0.2 版默认 torch.compile；设 NO_TORCH_COMPILE=1 走即时模式，4.7 秒音频嵌入约 0.16 秒（CPU）。
部分导出报“operands could not be broadcast”水印在 16kHz 上生成再重采样回来，奇数长度会少 1 个样本；补齐到原长度。
读引擎流式 WAV 得到 0 帧流式响应的 WAV 头里数据长度是 0，soundfile 照此读不到样本；跳过 44 字节头直接按 PCM 解析。
OmniVoice 的 instruct 和参考音频一起用效果不稳实测“low pitch”反而升调、“whisper”无效；instruct 只用于不带参考的“文字设计声音”，生成后把选中的候选作为参考再克隆（相似度 0.74-0.84）。
Tauri 打包报“重分析点”（os error 4395）在打包环境里 %LOCALAPPDATA%\tauri\NSIS 被文件虚拟化，删除重建失败；清掉该目录后重新 tauri build。

10. 接入自己的项目

  1. 装好 CharaVoice（安装包或 setup.bat），在“模型”页装好必需组件；只给 Agent 用可以直接运行后端。
  2. 从 data/runtime.json 读 base_url 和 token，以 Authorization: Bearer 调用上面的接口；或者直接接 MCP。
  3. 需要界面状态联动时订阅 WS /v1/events?token=…：state（idle/listening/thinking/speaking）、level（source=speak/mic，0-1）。
  4. 只能用于本人或已获授权的声音；接口输出带水印，可用 POST /v1/audio/watermark/detect 检测。
