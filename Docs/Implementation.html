CharaVoice 技术实现

CharaVoice 是一个 Windows 本地软件：整理某个人的声音素材，用 GPT-SoVITS 学习声线，再通过 MCP、HTTP 和命令行让 Agent 用这个声音说话、听用户说话。本文讲清楚各部分怎么实现、有哪些要注意的地方，方便复现或接入自己的项目。

1. 整体结构

  • 引擎永远是独立进程，后台不 import 引擎代码。GPT-SoVITS 整合包自带 Python，OmniVoice 有自己的虚拟环境，和后台的 3.11 环境互不影响。
  • 后台用 Windows 作业对象（JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE）托管引擎子进程：后台怎么退出，引擎都会被系统回收，不留占显存的进程。
  • 界面只是后台的一个客户端：所有数据和任务都在后台，界面通过 HTTP 调用、通过 WS /v1/events 收状态。所以窗口关掉、重开，或者 Agent 在没有窗口时调用，行为一致。

2. 后台服务的生命周期

后台可能由三方启动：打开的软件、Agent 的 MCP 调用、命令行。规则是全机只有一个后台，谁先来谁启动，其他的复用。

环节做法
MCP 启动后台MCP 客户端会把它启动的服务器进程放进作业对象，退出时结束整个作业，而且通常不允许子进程脱离。所以 stdio 版 MCP 通过 PowerShell 的 Invoke-CimMethod Win32_Process Create 让 WMI 创建后台（无窗口、不在作业里），Agent 退出后后台继续运行，之后打开的软件也直接复用；WMI 不可用时退回分离的 Popen。
空闲释放idle.py 每 30 秒检查一次。没有合成、训练、录音时，空闲 idle.unload_minutes（默认 10）分钟后停止语音引擎、释放显存，下次请求自动重新加载（约 15 秒）；没有界面连着 /v1/events 且空闲 idle.exit_minutes（默认 60）分钟后，后台退出。
软件退出后台监视启动它的外壳进程。外壳退出时：如果最近（exit_minutes 以内）有具名 Agent 调用过，后台留下继续服务，把标准输出、错误重定向到 NUL（外壳的管道已经关闭），之后按空闲规则自己退出；否则立即退出。
界面上的控制GET /v1/service 返回运行时间、空闲时间、引擎状态和显卡占用；POST /v1/service/unload、/v1/service/stop 对应“立即释放显存”和“停止后台服务”。停止后外壳暂停自身的自动重连（set_backend_paused），否则隐藏的小窗会把后台又拉起来。
窗口与托盘点关闭时界面拦截 onCloseRequested：按设置缩到托盘或退出，第一次询问。托盘菜单有“打开 / 释放显存 / 停止后台服务 / 退出”，后两项需要口令，由界面执行。主窗口被销毁时外壳调用 app.exit，因为隐藏的录制小条、听写小窗会让程序在没有可见窗口的情况下一直运行。tauri-plugin-single-instance 保证再次启动只是把已有窗口调到前台。

3. 素材库：录制与截取

要点做法
数据一个素材文件夹就是一个声音（voice.json 里 folder: true，带素材语言 ja / zh / en）。片段存在 data/voices/<id>/clips/，元数据在 clips.json（时长、来源录音、截取区间、CAM++ 声纹）。原始录音以 FLAC 存在 data/recordings/，片段可以随时重新裁剪；没有片段引用的录音在放置 3 天后自动清理。
快捷键录制全局快捷键按顺序尝试 Ctrl+Alt+R、Ctrl+Alt+Shift+R、Alt+Shift+R、Ctrl+Alt+F9，注册第一个空闲的（不用 Ctrl+Shift+R，它是浏览器的强制刷新）。按下后显示一个预先建好、不抢焦点的置顶小条，由它调用 /v1/simple/record/toggle，所以主窗口最小化时也能用。同一次按键 700 毫秒内只触发一次。
回环录音PyAudioWPatch 把每个 WASAPI 输出设备复制成 [Loopback] 输入设备。PyAudio 实例、打开流和读流必须在同一线程，否则报 PortAudio -9999；设备空闲时回环不给数据，按真实时间补静音。
截取建议Silero VAD 切出语音段，首尾建议为第一段前 0.2 秒到最后一段后 0.3 秒。每段（≥0.8 秒）算 CAM++ 声纹，与文件夹已有片段的平均声纹比较（没有片段时用第一段作基准，用户可以双击任意段改基准）；低于 0.5 的段默认去掉。实测同一人各段 0.55–0.73，混入的另一个人 0.26–0.36。
素材语言新建文件夹时可以指定语言，也可以留空：第一个片段保存时用 SenseVoice 识别语种，写回文件夹。

4. 克隆流水线

  • 人声分离可以在界面上关掉（“去除背景音乐”），素材本来就干净时更快。它用一个很薄的驱动脚本 engine_scripts/uvr_separate.py，由整合包的 Python 执行；输入先转成 44.1 kHz 立体声，裁剪后的多个保留段拼成一个文件（段间垫 1 秒静音）一次分离。
  • 质量分 = 时长分 × 信噪比分 × 削波惩罚，另记录分离前的伴奏电平 bgm_db，重新训练时用来剔除伴奏重的句子。
  • 训练期间语音合成暂停（返回明确的提示），训练前先停掉推理引擎，批量按空闲显存 GB ÷ 2 估算。

5. 转写校对

训练用的文字来自 SenseVoice，它不给置信度。CharaVoice 的做法是同一段音频识别两次：一次自动判断语种，一次强制用文件夹的素材语言（结果存为 asr_alt，并记下语言 asr_alt_lang）。两次结果相似度低于 0.9，就说明识别器拿不准。

规则标为“可能有误”的情况
通用没有识别出文字；两次识别不一致；同一个字连续重复 4 次以上
日语没有假名（可能识别成了中文）；句中有多余的问号、感叹号；含字母；假名和汉字少于 60%；每秒字数不在 2.5–11 之间
中文含假名；汉字少于 50%；句中有多余的问号、感叹号；每秒字数不在 1.5–9 之间
英语含中日文字；每秒词数不在 0.8–5.5 之间

用户在校对界面改字、排除句子或换参考音频。参考文字立即生效；改了训练文字后点“重新学习”，会沿用这些句子直接训练，不再重新切句和转写。

6. 训练与逐轮选优

要点做法
底模默认 v2ProPlus：同样 10 分钟素材，比 v2Pro、V5 turbo LoRA 等更像，速度与 v2Pro 相同。与没参与训练的真人录音比，CAM++ 相似度 LJSpeech 0.88（v2Pro 0.81）。
参数传递和 webui.py 一致：准备脚本读环境变量（inp_text、inp_wav_dir、opt_dir、version、is_half 等）；训练脚本读由模板改写的配置。语义 token 由底模自己的量化器提取，按底模分别存成 6-name2semantic-<版本>.tsv。用 runtime\python.exe -s 执行。
目录实验目录与权重都放在声音自己的文件夹（train/exp、weights/），不写引擎目录。启动 s2 前必须先建 exp/logs_s2_<版本>，否则第一次保存检查点就失败。
断点与进度s2 从最新的 G_/D_ 检查点续，s1 由 Lightning 从 ckpt/ 续；进度解析 ====> Epoch: N 和 Epoch N: xx%。取消用 taskkill /T 结束整个进程树。

重新训练：干净素材 + 逐轮比较

从视频、游戏里录的素材常带伴奏残留和底噪，训练后的声码器会把 s、sh 这类擦音合成成没有结构的噪声，听起来像机器音。重新训练按下面的步骤处理：

  1. 整理干净训练集（写到 dataset/clean/，原片段不动）：分离前伴奏电平 bgm_db 高于 −10 dB 的句子剔除；底噪能听到的句子（10% 分位能量与 95% 分位相差不到 50 dB）做一次温和的维纳滤波。剩下不足 60 秒就停止，并说明原因。
  2. 训练并保留每一轮：SoVITS 训练 8 轮，每轮的权重都留下（keep_s2）。
  3. 逐轮试听比较：每个候选（含原模型）合成同一组测试句，测三项：4.5–11 kHz 擦音段的频谱平坦度（越低越有结构）、嘶声电平、与文件夹声纹的相似度。
  4. 选择与清理：在相似度不低于原模型 97% 的候选里取平坦度最低的；新的各轮都不如原模型就保留原模型。只保留胜出的一版，其余权重删除。

7. 朗读与去齿音

环节做法
分句与流式界面按句末标点和换行分句（过短的并入后句，过长的在逗号处再切），每句请求 /v1/audio/speech（stream: true，WAV 头之后是裸 PCM），在同一个 AudioContext 上首尾相接排队播放；上一句数据到齐就请求下一句。首包是长度为 0 的 WAV 头，要跳过 44 字节按 PCM 解析。
预热切换文件夹或合成方式时调用 /v1/simple/folders/<id>/warm，用一句很短的话（如“你好。”）让引擎加载这个声音的权重和参考，真正朗读时首句不用等。
语速每个文件夹单独设置，默认 0.9 倍（GPT-SoVITS 默认语速对朗读偏快）。Agent 调用时同样生效。
合成方式“标准”用文件夹自己的 GPT-SoVITS 结果；“音质优先”用 OmniVoice 以文件夹里最干净的几句（拼到 10 秒内）零样本克隆，擦音更清楚，相似度略低（0.81 对 0.86）。切换引擎要先停另一个，约 15 秒。

去齿音

阈值按说话人自适应：从文件夹的句子里测一次这个人平时的齿音占比中位数 sib_norm，存进 clips.json。

8. 语种判断

调用方没指定语言时（或文件夹的“朗读语言”是自动），按文字判断：

  • 中文、日语句子里夹的英文单词保留在原语种里读（GPT-SoVITS 的 zh、ja 模式能读中英、日英混合）。
  • 显式传入的 language 优先。说的语言和素材语言不同时，接口返回 accent_warning，界面和 MCP 都会提示可能带口音。
  • 跨语言的音色和语调受方法限制：GPT-SoVITS 里语调由 GPT（语义模型）和它接着念的参考句决定，让 GPT 跟着母语参考走，语调更地道，但相似度明显下降（中文 0.78 → 0.56）。实测日语素材训练的声音：日语 0.85、英语 0.77、中文 0.74。要自然的另一种语言，只能用这个人说该语言的素材。

9. 按住说话

  1. 外壳注册全局快捷键（Ctrl+Alt+V，被占用时依次尝试 Ctrl+Alt+Shift+V、Alt+Shift+V、Ctrl+Alt+F10），按下、松开两个边沿都发给界面，界面调用 /v1/ptt/start、/v1/ptt/stop。
  2. ptt.py 打开麦克风缓存 16 kHz 音频；松开后用 Silero VAD 只留下语音（前后补一点），SenseVoice 在 CPU 上识别并判断语种。
  3. 默认用设置里选的声音（ptt.voice）念出来，也可以关掉“自动念”只返回文字。实测松开到开始念 0.5–1.4 秒。
  4. /v1/ptt/simulate 用音频文件代替麦克风，方便自动化测试。

10. MCP 与其他接口

接口说明
MCP 工具list_voices、speak、synthesize、stop、listen。基于 MCP Python SDK 2.x 的 MCPServer；声音就是素材库里已就绪的文件夹。
stdiocharavoice-mcp（源码版）或 charavoice-backend.exe mcp（安装版）。它本身不加载模型，只是后台的 HTTP 客户端，需要时按第 2 节自动启动后台。
Streamable HTTP挂在后台的 /mcp：自己建 StreamableHTTPSessionManager(app=server._lowlevel_server)，在 FastAPI 的 lifespan 里 async with manager.run()；路由用一个检查口令后转给 manager.handle_request 的 ASGI 对象，并限定 Host / Origin 为本机，防止 DNS 重绑定。
按 Agent 分配声音调用方名字依次取：环境变量 CHARAVOICE_AGENT、请求头 X-CharaVoice-Agent、MCP 握手里的 client_info.name。记在 data/agents.json，没指定 voice 时用绑定的声音。
口令运行时口令每次启动重新生成，写在 data/runtime.json（命令行和 stdio MCP 自动读取）；长期有效的 Agent 口令在 data/agent_token，给需要写进配置的 HTTP 客户端用。
HTTPOpenAI 兼容的 /v1/audio/speech、/v1/audio/transcriptions；便捷接口 /v1/speak、/v1/listen；事件 WS /v1/events（状态与实时音量）。非流式输出带 AudioSeal 水印和“AI 合成”元数据。能力清单 /.well-known/charavoice.json。
claude mcp add charavoice -- "<CharaVoice 目录>\.venv\Scripts\charavoice-mcp.exe"

11. 安装包

  • 后台用 PyInstaller 冻结为单目录 charavoice-backend.exe（同一个 exe 是后台 serve、命令行和 stdio MCP），作为 Tauri 资源打进 NSIS 安装包（按用户安装）。mcp 包不要整体收集（mcp.cli 依赖 typer），只收 mcp.server、mcp.shared。
  • 冻结后的后台默认数据目录是 %LOCALAPPDATA%\io.github.rudans.charavoice，与 Tauri 的 identifier 一致，所以命令行和 MCP 不需要配置就能找到运行中的后台；CHARAVOICE_HOME 可以改到别处。
  • 模型与引擎不进安装包，在“模型”页下载：断点续传（Range）、进度事件，GPT-SoVITS 整合包用下载来的 7zr.exe 解压，OmniVoice 用下载来的 uv 建环境。删除只允许删除数据目录里的内容。
  • 构建：scripts\build-installer.bat。用 uv 建的虚拟环境里没有 pip，脚本检查 PyInstaller 时用 import PyInstaller，缺了再用 uv pip install 安装。

12. 踩过的问题

现象原因与处理
Agent 退出后后台也没了MCP 客户端结束了作业对象里的所有进程。改由 WMI 创建后台（第 2 节）。
MCP 连上了一个已经退出的后台旧的 runtime.json 还在，端口又被新进程占了，只看 /health 会误判。改为带口令请求 /v1/status。
关掉主窗口后程序还在后台跑隐藏预建的录制小条、听写小窗让程序在没有可见窗口时继续运行，快捷键也还生效。主窗口销毁时显式退出；需要常驻时缩到托盘。
“音质优先”没有效果文件夹声音到引擎的路由放在了构造请求之后。路由要在 build_request 之前。
界面不停地预热、切换引擎两个引擎都发“就绪”事件，引擎状态被 OmniVoice 覆盖。界面的引擎状态只看 GPT-SoVITS，预热只在切换文件夹或合成方式时触发。
按一次快捷键，录音开始又立刻停止快捷键事件和小条的自动切换各触发了一次。小条只在自己的开始按钮上自动切换，并加 700 毫秒去抖。
引擎日志乱码python -I 会忽略 PYTHONIOENCODING，子进程按系统 ANSI 代码页输出；读管道时用 locale.getencoding() 解码。
偶发合成卡几分钟显卡被其他程序占满时会出现；后台 90 秒无输出就报错并自动重启引擎。
AudioSeal 报找不到 cl0.2 版默认 torch.compile；设 NO_TORCH_COMPILE=1 走即时模式，4.7 秒音频嵌入约 0.16 秒（CPU）。
打包报“重分析点”（os error 4395）在打包环境里 %LOCALAPPDATA%\tauri\NSIS 被文件虚拟化，删除重建失败；清掉该目录后重新 tauri build。

13. 接入自己的项目

  1. 按 README 运行 setup.bat，或用安装版并在“模型”页装好必需组件；只给 Agent 用可以只运行后台。
  2. 最简单的方式是接 MCP。要直接调用 HTTP，从 data/runtime.json 读 base_url 和 token，以 Authorization: Bearer 调用。
  3. 需要界面联动（比如角色说话时的动画）时订阅 WS /v1/events?token=…：state（idle / listening / thinking / speaking）和 level（0–1 的实时音量）。
  4. 只能用于本人或已获授权的声音；接口输出带水印，可用 POST /v1/audio/watermark/detect 检测。

也可以把仓库代码和这份文档一起交给 AI，让它帮你读懂结构、写接入代码。
