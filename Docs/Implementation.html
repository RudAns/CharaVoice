CharaVoice 技术实现说明

本地角色声音服务：GPT-SoVITS 合成与微调、sherpa-onnx 听写、素材流水线、Tauri 界面与 Agent 接口。本文只讲接入和复现所需的要点。

1. 整体结构

  • 引擎永远作为独立进程运行，后端不 import 它的代码。整合包自带 Python，和后端的 3.11 虚拟环境互不影响。
  • 后端用 Windows 作业对象（JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE）托管所有子进程；Tauri 用 set_process_group(true) 启动后端。任何一层退出，下面的进程都会被系统回收，不留占显存的僵尸进程。
  • 后端另外监视父进程 PID（--parent-pid），Tauri 崩溃时自行退出。

2. 合成（说）

  1. 启动：runtime\python.exe -I api_v2.py -a 127.0.0.1 -p 9880 -c data/engine/tts_infer.yaml，配置只写 custom 段（device、is_half、version、权重路径）。api_v2 没有健康检查接口，用 GET /docs 探活。
  2. 每个声音的请求带自己的参考音频与参考文本；权重不同就先调 /set_gpt_weights、/set_sovits_weights（引擎会按文件自动识别版本）。
  3. POST /tts 用 streaming_mode=1（逐句返回）：首包是只有头的 WAV，之后是裸 PCM，按 2 字节对齐切块，边收边播放。
  4. 播放线程每 30ms 写一块、同时算电平推给界面，所以 Agent 通过接口说话时圆环也会动。
参考音频必须 3-10 秒（引擎在 TTS.py 里硬性检查）。参考文本为空时后端用 SenseVoice 自动转写。语种按文字自动判断：含假名为日语，含汉字为中文，否则英语。

3. 听写（听）

麦克风 16kHz → 每 30ms 一块送 Silero VAD（is_speech_detected() 的上升沿推 speech_start）→ VAD 弹出片段时推 speech_end → 独立线程用 SenseVoice 识别并推 transcript（文字、语种、情绪）。单次 listen 把间隔小于 turn_silence（默认 1.2 秒）的片段拼成一句再返回。角色说话时默认暂停听写，避免录进自己的声音。

4. 素材流水线

  • 裁剪后的多个保留段拼成一个文件（段间垫 1 秒静音）一次性分离；切出的句子时间再换算回原始素材时间（落在垫片里的就吸附到最近的保留段边界）。
  • 人声分离用一个很薄的驱动脚本 engine_scripts/uvr_separate.py，由整合包的 Python 执行，调用它的 Roformer_Loader._path_audio_()；输入需先转成 44.1kHz 立体声，输出 <名字>_vocals.wav。
  • 声纹相似度：sherpa-onnx SpeakerEmbeddingExtractor + 3D-Speaker CAM++（中英通用）。默认目标是该声音的参考音频，也可以用勾选的片段平均。实测同一人 0.86-0.96，不同人约 0.02-0.15。
  • 质量分 = 时长分 × 信噪比分 × 削波惩罚（信噪比用帧能量 90/10 分位估算，只作排序参考）。
  • 回环录音：PyAudioWPatch 把每个 WASAPI 输出设备复制成 [Loopback] 输入设备。PyAudio 实例、打开流和读流必须在同一线程，否则报 PortAudio -9999；设备空闲时回环不给数据，按真实时间补静音。

5. 训练

要点做法
参数传递和 webui.py 一致：准备脚本全部读环境变量（inp_text、inp_wav_dir、opt_dir、i_part/all_parts、version、is_half…）；训练脚本读由模板改写的配置（configs/s2v2Pro.json、configs/s1longer-v2.yaml）。用 runtime\python.exe -s 执行。
目录实验目录与权重输出都指向声音自己的文件夹（data/voices/<id>/train/exp、weights/），不写引擎目录。启动 s2 前必须先建 exp/logs_s2_<版本>，否则第一次保存检查点就失败。
断点续训s2 从 logs_s2_<版本> 里最新的 G_/D_ 检查点续；s1 由 Lightning 从 ckpt/ 续。准备阶段产物存在就跳过。所以“继续训练”就是用同一目录重新跑。
显存训练前停掉推理引擎，并在训练期间拒绝合成请求（返回明确提示）。批量按空闲显存 GB ÷ 2 估算（webui 用总显存 ÷ 2）。
进度s2 解析 ====> Epoch: N；s1 解析 Lightning 的 Epoch N: xx%。中断用 taskkill /T 结束整个进程树（含 DataLoader 子进程）。

6. Agent 接口

接口说明
POST /v1/audio/speechOpenAI 兼容；model/voice = 声音 id；language、response_format、stream、play（false 只返回音频）。非流式输出带 AudioSeal 水印和“AI 合成”元数据。
POST /v1/speak播放并返回 JSON；wait=true 等播完。
POST /v1/audio/transcriptionsOpenAI 兼容转写，返回 text / language（verbose_json 带分段）。
POST /v1/listen、WS /v1/listen听一句；实时事件 speech_start / speech_end / transcript。
MCP（stdio）speak(text, voice?, language?, wait?)、list_voices()、listen(timeout?)；基于 MCP Python SDK 2.x 的 MCPServer（v1 的 FastMCP 已改名）。
claude mcp add charavoice -- "<CharaVoice 目录>\.venv\Scripts\charavoice-mcp.exe"

7. 踩过的问题

现象原因与处理
引擎日志乱码python -I 会忽略 PYTHONIOENCODING，子进程按系统 ANSI 代码页输出；读管道时用 locale.getencoding() 解码。
偶发合成卡几分钟显卡被其他程序占满（模拟器、编辑器）时会出现；后端 90 秒无输出就报错并自动重启引擎。CUDA Graph 首次遇到新长度需要捕获，启动后先做一次预热。
两个窗口同时检测到后端退出，拉起两个后端Rust 侧用异步互斥锁串行化 backend_info；后端发现端口已占用直接退出。
热更新后 WebGL 退回静态图组件卸载时不要 loseContext()，同一个 canvas 可能被复用；只释放缓冲区和程序。
AudioSeal 报找不到 cl0.2 版默认 torch.compile；设 NO_TORCH_COMPILE=1 走即时模式，4.7 秒音频嵌入约 0.16 秒（CPU）。

8. 接入自己的项目

  1. 运行 setup.bat 装好环境、模型和引擎；只给 Agent 用可以直接 start-backend.bat。
  2. 从 data/runtime.json 读 base_url 和 token，以 Authorization: Bearer 调用上面的接口；或者直接接 MCP。
  3. 需要界面状态联动时订阅 WS /v1/events?token=…：state（idle/listening/thinking/speaking）、level（source=speak/mic，0-1）。
  4. 只能用于本人或已获授权的声音；接口输出带水印，可用 POST /v1/audio/watermark/detect 检测。
